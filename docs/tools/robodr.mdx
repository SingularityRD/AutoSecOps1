## Check RoboDR action policy

Action ID: `tools.robodr.check_action_policy`

Check a robot action against the SOC-side rules before it is prepared: catalog action, how many sign-offs it needs (single or two-person), and morphology (safe_pause, request_safe_state and rollback_config only for wheeled_mobile, arm, aerial or other; never rollback_config on a quadruped). Advisory: request_action enforces the same rules and the platform sign-off itself.

Reference: [https://docs.singularityrd.com/integrations/robodr-tools](https://docs.singularityrd.com/integrations/robodr-tools)

Catalog action, wire name (e.g. robot_restrict_motion) or plain name.

</ParamField>

<ParamField path="advertised_actions" type="array[string] | null">

The robot snapshot's `actions` list (plain names).

Default: `null`.

</ParamField>

<ParamField path="morphology" type="string | null">

Robot morphology from the robot snapshot. De-energising actions need wheeled_mobile, arm, aerial or other; anything else is refused.

Default: `null`.

</ParamField>

## Request RoboDR robot action

Action ID: `tools.robodr.request_action`

Send one signed-off catalog action request (robot_restrict_motion, robot_quarantine_node, robot_isolate_network, robot_record_evidence, robot_safe_pause, robot_request_safe_state, robot_rollback_config) to a robot's control plane. Refuses unless platform form submissions prove the requester and one approver (two for the two-person actions), all different platform users, signed off this exact request. The robot judges it against its safety state and may refuse it. The current RoboDR release records but never executes: recorded_not_executed is reported as not applied.

## Verify RoboDR finding signature

Action ID: `tools.robodr.verify_finding_signature`

Verify the detached Ed25519 per-finding signature (robodr-finding-sig) over the raw record value. Returns valid, reason and the signing key id. Verification is strict and never re-serialises the value.

Reference: [https://docs.singularityrd.com/integrations/robodr-tools](https://docs.singularityrd.com/integrations/robodr-tools)

### Input fields

<ParamField path="public_key_hex" type="string" required>

Ed25519 public key of the robot's finding key, 64 hex digits (`public_hex` of its robodr-blackbox key file).

</ParamField>

<ParamField path="signature" type="string | object | null" required>

The signature object &#123;alg, key_id, sig&#125;, as the robodr-finding-sig header JSON string or as an object (the ingest line's `sig`).

</ParamField>

<ParamField path="value" type="string" required>

The record value exactly as received. Any re-formatting (pretty printing, key reordering, re-escaping) breaks the signature.

</ParamField>

<ParamField path="key_id" type="string | null">

Expected key id. When set, a signature by another key id fails.

Default: `null`.

</ParamField>

<ParamField path="robot_id" type="string | null">

Robot the public key is registered for. When set, the finding must name this robot in entity_context.robot.id.

Default: `null`.

</ParamField>
