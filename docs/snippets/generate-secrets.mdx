AutoSecOps requires four secrets and a Temporal payload encryption keyring. Generate them with `openssl`:

```bash
# Service key (hex, 32 bytes) — used for internal service-to-service JWT signing
openssl rand -hex 32

# Signing secret (hex, 32 bytes) — used for webhook URL signing and HMAC operations
openssl rand -hex 32

# User auth secret (hex, 32 bytes) — used for password reset, email verification, OAuth state, and OIDC key derivation
openssl rand -hex 32

# DB encryption key (Fernet-compatible base64, 32 bytes) — used for encrypting secrets at rest
openssl rand 32 | base64 | tr -d '\n' | tr '+/' '-_'

# Temporal payload encryption keyring (JSON, 32-byte root secret) — encrypts workflow history
printf '{"current_key_id":"v1","keys":{"v1":"%s"}}' "$(openssl rand -hex 32)"
```

<Warning>
  Store these securely. Losing `AUTOSECOPS__DB_ENCRYPTION_KEY` makes encrypted credentials unrecoverable.
  Losing `AUTOSECOPS__SIGNING_SECRET` invalidates existing webhook URLs and agent channel endpoint URLs.
  Losing a key in `TEMPORAL__PAYLOAD_ENCRYPTION_KEYRING` makes the workflow history encrypted under it unreadable.
</Warning>

See [Where to store them](/self-hosting/security#where-to-store-them) for the recommended storage on each deployment target, and which of these secrets can be rotated.
