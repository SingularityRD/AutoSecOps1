### Network

| Variable | Default | Description |
| :------- | :------ | :---------- |
| `PUBLIC_APP_PORT` | `80` | Port the reverse proxy listens on. |
| `PUBLIC_APP_URL` | `http://localhost:${PUBLIC_APP_PORT}` | Public URL users visit to reach the AutoSecOps UI. |
| `PUBLIC_API_URL` | `${PUBLIC_APP_URL}/api` | Public URL for the AutoSecOps API, used by the browser and for webhook callbacks. |
| `INTERNAL_API_URL` | `http://api:8000` | Internal URL that other services use to reach the API container. |
| `AUTOSECOPS__TRUSTED_PROXY_CIDRS` | `127.0.0.1/32` | Space-separated proxy CIDRs that Caddy trusts when deriving the client address from `X-Forwarded-For`. Set this when another proxy or load balancer runs in front of Caddy. |
| `AUTOSECOPS__OUTBOUND_ALLOWED_PRIVATE_CIDRS` | | Comma-separated IPs or CIDRs, e.g. `10.0.12.34/32,10.42.0.0/16`, that custom LLM providers (LiteLLM, vLLM, Ollama, custom sources) and remote MCP servers may resolve to. AutoSecOps rejects private, loopback, and link-local destinations with `Host is not allowed` unless they are listed here. Set it on `api`, `agent-worker`, `litellm`, and `agent-executor`. See [Private endpoints](/agents/llm-providers#private-endpoints). |
| `AUTOSECOPS__OUTBOUND_PROXY_URL` | | HTTP or HTTPS forward proxy that LLM provider, model discovery, and remote MCP requests go through, e.g. `http://proxy.example.internal:3128` or `http://user:password@10.0.0.8:3128`. Percent-encode special characters in credentials. AutoSecOps still resolves each target locally and rejects private destinations before it uses the proxy. `HTTP_PROXY` and `HTTPS_PROXY` have no effect on these requests. Set it on `api`, `agent-worker`, `litellm`, and `agent-executor`. See [Corporate proxy](/agents/llm-providers#corporate-proxy). |
| `AUTOSECOPS__OUTBOUND_NO_PROXY` | | Comma-separated hostnames, IPs, or CIDRs that skip `AUTOSECOPS__OUTBOUND_PROXY_URL` and connect directly, e.g. `vllm.example.internal,10.0.12.0/24`. A hostname also matches its subdomains. |
| `AUTOSECOPS__AUDIT_TRUSTED_PROXY_CIDRS` | loopback + private ranges | Comma-separated CIDRs of proxies behind which the API runs (Caddy, the UI container, a load balancer). `X-Forwarded-For` entries from these hops are skipped when resolving the client IP for audit logs. |
| `AUTOSECOPS__PLATFORM_ADMIN_IP_ALLOWLIST_BYPASS` | `false` | Break-glass override for the API service. When `true`, AutoSecOps skips the [platform admin IP allowlist](/manage-platform/ip-allowlist#platform-admin-ip-allowlist) so a locked-out platform admin can recover. Organization allowlists still apply. Remove it after recovery. |

### Executor

| Variable | Default | Description |
| :------- | :------ | :---------- |
| `AUTOSECOPS__EXECUTOR_BACKEND` | `direct` | Execution mode for actions, agents, registry sync, and Python scripts. `direct` runs without nsjail; `nsjail` requires nsjail isolation. `ephemeral` is a compatibility alias for `nsjail`. |
| `AUTOSECOPS__EXECUTOR_CLIENT_TIMEOUT` | `300` | Maximum seconds one action function call may run. The `executor` service caps each call at this value and uses it as the action's timeout when `timeout` is `0`. A template action's total runtime and `core.script.run_python` scripts follow the action's own `timeout` instead. The Compose files and the Fargate module do not pass this variable to the `executor` service, so set it on that container directly to raise the cap. |
| `AUTOSECOPS__EXECUTOR_ENV_PASSTHROUGH` | | Comma-separated names of extra `executor` environment variables that actions read in the `direct` backend, such as `CUSTOMER_REGION,HTTP_TIMEOUT`. Actions otherwise receive only `PATH`, `HOME`, locale, temp-directory, Python path, CA-bundle, and proxy variables plus the run's SDK context. AutoSecOps ignores platform names (`AUTOSECOPS__*`, `TEMPORAL__*`, `AWS_*`, `SENTRY_*`, `REDIS_*`, `PG*`, and similar) and credential-like names (`*_KEY`, `*_SECRET`, `*_PASSWORD`, `*_TOKEN`, `*_URI`, `*_URL`, and similar). Store credentials as workspace secrets. The Compose files, Helm chart, and Fargate module do not pass this variable, so set it on the `executor` container directly. |
| `AUTOSECOPS__SANDBOX_DEFAULT_MEMORY_MB` | `2048` | Aggregate cgroup v2 memory limit in MiB per `core.script.run_python`, dependency-install, and custom action sandbox, shared by its processes. Applied by the nsjail backend. Exceeding it during script or action execution fails as `sandbox.resource_limit_exceeded`; an over-budget dependency installation fails as a package installation failure. The container memory limit still applies on top. See [Resource limits](/self-hosting/security#resource-limits). |
| `AUTOSECOPS__SANDBOX_ADDRESS_SPACE_MB` | Uncapped | Per-process virtual address-space cap in MiB for action, Python, and dependency-install sandboxes. Requires nsjail. The cgroup memory budget bounds RAM; set a positive integer to also cap address space. |
| `AUTOSECOPS__SANDBOX_PYPI_INDEX_URL` | `https://pypi.org/simple` | PyPI index for `core.script.run_python` dependencies and custom registry sync, e.g. an internal mirror such as `https://pypi.example.internal/simple`. Read by the `executor` service. See [Mirror PyPI and npm](/self-hosting/air-gapped#mirror-pypi-and-npm). |
| `AUTOSECOPS__SANDBOX_PYPI_EXTRA_INDEX_URLS` | | Comma-separated extra PyPI index URLs for the same installs. |
| `AUTOSECOPS__RESULT_EXTERNALIZATION_ENABLED` | `true` | Store large action results in blob storage instead of Temporal history. |
| `AUTOSECOPS__RESULT_EXTERNALIZATION_THRESHOLD_BYTES` | `128000` | Byte threshold above which payloads are externalized to blob storage. |
| `AUTOSECOPS__WORKFLOW_ARTIFACT_RETENTION_DAYS` | `30` | Retention period in days for workflow artifacts. Objects older than this are automatically deleted via S3 lifecycle rules. Set to `0` to disable. |
| `AUTOSECOPS__ACTIVITY_HEARTBEAT_TIMEOUT` | `60` | Seconds Temporal waits for a heartbeat from an executor activity before failing it and retrying on a healthy worker. Set to `0` to disable. Read by the `worker` service. The Compose files and the Fargate module do not pass this variable through, so set it on that container directly. To disable heartbeats, set this and `AUTOSECOPS__ACTIVITY_HEARTBEAT_INTERVAL` to `0` together. |
| `AUTOSECOPS__ACTIVITY_HEARTBEAT_INTERVAL` | `30` | Seconds between heartbeats from executor activities. A value at or above `AUTOSECOPS__ACTIVITY_HEARTBEAT_TIMEOUT` lets Temporal fail the activity between two heartbeats. Set to `0` to disable heartbeats. Read by the `executor` service and not passed through by the Compose files or the Fargate module, so set it on that container directly. `0` alone stops the executor heartbeating while the worker still expects one every `AUTOSECOPS__ACTIVITY_HEARTBEAT_TIMEOUT` seconds, which fails actions that run longer than that. |

These settings control the [tunnel gateways](/self-hosting/kubernetes#tunnels) that the `api` service runs on Kubernetes. Executors read `AUTOSECOPS__TUNNEL_GATEWAY_HOST_TEMPLATE` and `AUTOSECOPS__TUNNEL_GATEWAY_PORT` to find a tunnel's gateway.

| Variable | Default | Description |
| :------- | :------ | :---------- |

| `AUTOSECOPS__TUNNEL_GATEWAY_IMAGE` | `ghcr.io/singularityrd/autosecops-tunnel-gateway:<version>` | Gateway image. Defaults to the running AutoSecOps version; set `repository@sha256:<digest>` to pin an immutable image. |
| `AUTOSECOPS__TUNNEL_GATEWAY_BLOCKED_CIDRS` | | Comma-separated CIDRs gateways never dial, such as the cluster's pod and service ranges. |
| `AUTOSECOPS__TUNNEL_GATEWAY_API_URL` | `AUTOSECOPS__API_URL` | Internal API URL that gateways load their policy from. |
| `AUTOSECOPS__TUNNEL_GATEWAY_HOST_TEMPLATE` | `tunnel-{tunnel_id}.<AUTOSECOPS__TUNNEL_GATEWAY_NAMESPACE>.svc.cluster.local` | Gateway hostname, with `{tunnel_id}` filled in per tunnel. |
| `AUTOSECOPS__TUNNEL_GATEWAY_PORT` | `8080` | Gateway proxy port. |
