A self-hosted AutoSecOps deployment runs the free feature set until you install a license key.
The license key lists the paid features (entitlements) your deployment may use and when it expires.
To buy or renew a license, contact [sales@singularityrd.com](mailto:sales@singularityrd.com).

Without a license, every deployment gets custom registry repositories and Workspace Chat.
All other entitlements, such as Git sync, case and agent add-ons, RBAC add-ons, service accounts, multi-workspace, Watchtower, external secret stores, agent channels, semantic search, forms, and tunnels, need a license that grants them.

## Install a license key

A license key is a single line of two base64url segments separated by a dot:

```text
eyJjdXN0b21lciI6Ii4uLiJ9.MEUCIQDx...
```

Set it as `TRACECAT__LICENSE_KEY` on every backend service: `api`, `worker`, `executor`, `agent-worker`, `agent-executor`, and `mcp`.

<Tabs>
  <Tab title="Docker Compose">
    Add the key to your `.env` file, then recreate the services.

    ```bash
    TRACECAT__LICENSE_KEY=eyJjdXN0b21lciI6Ii4uLiJ9.MEUCIQDx...
    ```

    ```bash
    docker compose up -d
    ```
  </Tab>
  <Tab title="AWS Fargate">
    Set the `license_key` Terraform variable, then apply.

    ```bash
    export TF_VAR_license_key="eyJjdXN0b21lciI6Ii4uLiJ9.MEUCIQDx..."
    terraform apply
    ```
  </Tab>
  <Tab title="Kubernetes">
    Add `TRACECAT__LICENSE_KEY` to the environment of the backend deployments, then roll them out.
  </Tab>
</Tabs>

AutoSecOps reads the key at process startup, so restart the services after you install or replace a key.

## Check license status

Platform admins see the license on the `License` page of the admin console at `/admin/license`, including its status, customer, expiry date, the entitlements the license grants, and the entitlements included without a license.
The same data is available from the API:

```bash
curl -H "Authorization: Bearer <superuser-token>" \
  https://tracecat.yourdomain.com/api/admin/license
```

The `api` service also logs the license status at startup.

| Status | Meaning | Paid entitlements |
| :----- | :------ | :---------------- |
| `missing` | No `TRACECAT__LICENSE_KEY` is set. | Off |
| `valid` | The signature verifies and the license has not expired. | On |
| `grace` | The license expired less than 14 days ago. | On |
| `expired` | The license expired 14 or more days ago. | Off |
| `invalid` | The key is malformed, or its signature does not verify. | Off |

## Expiry and grace period

When a license expires, AutoSecOps keeps its entitlements on for a 14-day grace period and logs a `LICENSE EXPIRED` warning at least once an hour.
After the grace period, paid features turn off and AutoSecOps logs an error.
Install a renewed key before the grace period ends to avoid interruption.

An invalid key never stops AutoSecOps from starting: the deployment runs with the free feature set and logs an error until you fix the key.
Turning paid features off keeps your data. Workflows, cases, and other records created with a paid feature stay in the database and become available again when you install a valid license.

## Feature flags

`TRACECAT__FEATURE_FLAGS` no longer turns on paid entitlements.
If you previously enabled paid features with flags such as `git-sync`, `case-tasks`, `rbac`, `agent-channels`, or `forms`, install a license key that grants them.
The `api` service logs a warning at startup that lists flags whose entitlements your license does not grant.

Flags that are not entitlements keep working.
The `forms` flag still gates forms, so forms need both the `forms` flag and a license that grants the `forms` entitlement.

## Multi-tenant deployments

With `TRACECAT__EE_MULTI_TENANT=true`, AutoSecOps ignores the license key and resolves entitlements from the tiers that platform admins assign to organizations.
