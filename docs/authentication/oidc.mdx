title: OIDC
description: "Authenticate into AutoSecOps using OpenID Connect: register an OIDC client with your IdP, map claims, and enable SSO sign-in across the platform."
---

## Configuration

In your `.env` file, enable the OIDC auth type.

```bash
AUTOSECOPS__AUTH_TYPES=oidc
```

## Required environment variables

Set the following variables for your provider:

- `AUTOSECOPS__PUBLIC_APP_URL`
- `OIDC_ISSUER`
- `OIDC_CLIENT_ID`
- `OIDC_CLIENT_SECRET`
- `OIDC_SCOPES` (optional, defaults to `openid profile email`)

## Instructions

<Steps>
  <Step title="Create an OIDC application with your identity provider">
    Register AutoSecOps as an application with your provider and allow the standard
    OpenID Connect scopes needed for sign-in.
  </Step>
  <Step title="Configure the redirect URI">
    Set the provider redirect URI to `<your-domain>/auth/oauth/callback`.

    For the local Docker Compose deployment, use `http://localhost/auth/oauth/callback`.
  </Step>
  <Step title="Configure environment variables in AutoSecOps">
    Add the public AutoSecOps URL, issuer URL, and client credentials to your `.env`
    file. AutoSecOps generates OAuth callback URLs from
    `AUTOSECOPS__PUBLIC_APP_URL`, so this must match the external URL users visit.

    Example:

    ```bash
    AUTOSECOPS__PUBLIC_APP_URL=https://autosecops.example.com
    OIDC_ISSUER=https://issuer.example.com
    OIDC_CLIENT_ID=autosecops
    OIDC_CLIENT_SECRET=replace-me
    OIDC_SCOPES="openid profile email"
    ```
  </Step>
  <Step title="Restart AutoSecOps">
    Restart the application so the new auth configuration is loaded.
  </Step>
</Steps>
